# 多租户 RAG 检索竞品研究对照验收

研究问题：在 200 个租户、10,000 名用户、2,000 万篇文档、每文档一个 1,536 维 float32 向量、每月 3,000 万查询且 10% 重排的场景下，比较 Elastic Cloud Hosted、Amazon OpenSearch Service 预置域、Azure AI Search 付费 Standard。检索 p95 <800ms 与每月 5,000 美元是待验证目标。

仅允许五个官方域名及其真实子域，区分部署形态、IAM 与文档/字段权限、商业权益、版本、区域和预览条件。价格缺失时保留公式及询价字段。完整问题、请求、评分标准与运行证据位于忽略目录 `.runs/competitive-rag-20261020/`，不提交凭据或运行数据。

中断之前已经留存的具体问题：

1. 五个官方域名被追加到每条 DeepSeek 查询，正常主题词与域名条件合计超过 128 字符，在请求发送前直接失败。10 份诊断缓存中记录了 27 条 `deepseek_invalid_query` 错误；这是缓存错误记录数，不等同于外部 API 请求次数。

3. 团队 SQL 死锁直接导致整个成本等子研究失败，缺少对数据库已确认回滚事务的有限恢复。

基线实际通过 DeepSeek Fetch 留存了 27 个网页文档，不能将搜索失败概括为所有网页访问均失败。

## 修复与边界

- `search_providers.py` 保留查询已有且符合范围的 `site:` 条件；没有显式站点条件时按域拆分，避免全局 OR 列表扩大查询语义或超过 128 字符。保留主题词、排除域和日期条件。沿用来源过滤、出网授权及并发控制；物理请求单独计数，候选按查询交错合并，避免前一个查询占满候选限额。扩展最多 24 条，截断明确报出，单条仍无法容纳时继续显式失败。
- `web/pipeline.py` 直接使用物理搜索次数，零次调用不再回退为查询数。
- `tasks/team_store.py` 仅对 `asyncpg.DeadlockDetectedError` 在整个 SQL 事务回滚后最多执行三次。沿用同一操作 ID，重新检查租约和领域约束，保留原子事件、回执及 outbox。连接异常、取消、权限失败和未知外部执行不进入重试。
- 最后一轮仍出现死锁，进一步以真实 `MemberLoop.guard()` 和数据库事务复现成员共享锁与任务更新之间的循环等待。`FencedTeamTransport.guard()` 统一先取得与账本写入一致的运行行锁，再进入成员/任务锁；没有新增锁表、迁移或配置。旧实现用例失败，新实现通过。相同运行的短数据库事务会串行，模型及网络请求不持有该事务锁。
- `web_progress.py` 的去重键区分实际物理查询，同一回执重放仍去重；研究提示优先直接读取用户提供且与任务相关的来源入口。
- 报告引用修复提示携带确定性检查得到的具体错误 URL、错误类型和位置；要求使用精确登记链接并移除未读取的来源入口。未放宽引用校验或将用户提供的 URL 自动视为证据。
- `sandbox_provider.py` 与 `sandbox/gateway.py` 让有界运行的 HTTP 客户端等待时间跟随冻结的模型调用上限并保留少量传输余量。第二轮修复中的三个失败调用均在约 180.2 秒断开，早于配置允许的 360 秒；修复避免独立的 180 秒客户端限时抢先结束调用。外层逻辑时限、取消及未知调用隔离继续生效，历史 baseline 模式沿用原等待时间。LiteLLM 的单次上游请求限时未修改。
- 恢复报告采用中性的“证据恢复报告”标题与“未完成原因”，避免将未执行评审的时间预算降级误报为“质量门禁未通过”。
- 未开启交接 Judge 或 Supervisor 最终质量阻塞；工具质量纠偏、Researcher 完成准入及报告审阅继续生效。没有新增环境开关、状态枚举或迁移。

新增远程测试强制产生真实双事务死锁，并验证只产生一次事件、一次接收回执和一次 outbox，已提交操作重放不执行变更。使用原始 TeamStore 同一用例失败，修复后通过。并非通过重新运行真实模型来处理数据库重试。

修复服务逐轮使用独立 Docker 标签 `competitive-rag-fix`、`competitive-rag-final`、`competitive-rag-timeout`，没有覆盖仍在运行的研究映像。API、Gateway、Controller、Publisher 中相应变更文件的 SHA-256 均核对工作区；Controller 指向同标签的 API Worker 映像。

## 后续问题复盘与代码修复

针对最后一轮 `685bf54590634fa6a3e4c5730b520922` 的规划响应、Supervisor 工具回执和完成路径继续离线排查，定位到以下确定性问题。本节为上述整题运行结束后的修复，没有替换历史报告或重新生成其质量评分。

1. **不同竞品任务被错误去重。** 运行记录中 `duplicate_tasks_suppressed=10`，AWS 的多个 TaskCreate 返回了已创建的 Elastic 任务 ID。去重键只有需求 ID、来源与依赖；这些字段在多竞品任务中可以相同。现加入具体研究主题和 Teams 负责人，仅合并同主题、同负责人、同依赖的在途请求。协作者模式同样按主题区分。完全相同请求仍去重，补研轮数、预算、所有权和交接状态没有放宽。
2. **八维清单被截掉前半段。** `_enumerated_object_facets()` 取最后一个“的”，把“语义重排的”当成整段共同对象，只保留后面的“条件和计费”等片段。现在遇到前文已有枚举时保留完整原文，不再把前面的混合检索、租户隔离、中英文、权限和语义重排对象丢掉。
3. **比较对象绑定失效。** 模型返回的 `Amazon OpenSearch Service 预置域` 与用户原文中的 `Amazon OpenSearch Service 的预置域` 不完全相同，Azure 也如此，最终所有需求的 subject 为空。匹配现在只容忍空白与连接词“的”的差异，绑定名称取用户原文，不引入模型别名或新增比较对象。Lead 的任务选择同时展示 subject、dimension_id，并说明普通研究任务的三项、同维度限制。
4. **原始业务场景丢失。** 规划模型在引用容量和查询量时使用了省略号；该引用按原有真实性规则被拒绝后，没有保留原始参数。现在从原始消息保留带明确场景标签的完整段落作为范围前提，不采纳省略号改写，不把给定参数升级为已经外部验证的事实；已有独立事实问题继续保留。
5. **报告预留资源没有用于报告。** `report_time_reserved` / `report_budget_reserved` 原来在 Writer 入口直接生成原始证据恢复稿，且报告恢复要求剩余时间大于三次最大调用时限。现在有证据时进入正常写作、引用检查及 Reviewer/Revisor；最大调用时限不再被当成最小耗时。实际预算拒绝或期限耗尽仍输出部分证据说明，保留未完成审阅标记。取消、失租和未知执行结果继续抛出；并存的未知结果优先于预算降级。研究实际受限时仍保留 partial 和停止原因，不因写作成功改成完整研究。

原交接及 Supervisor 收尾质量门禁仍然跳过，工具纠偏、Researcher 完成准入和报告评审仍然启用。没有新增配置、数据库迁移、状态枚举或评估分数。
