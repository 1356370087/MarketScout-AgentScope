# 原生研究效率与成本改造

本轮保留 AgentScope、ModelFactory、Gateway、来源准入和质量门禁。新版运行冻结契约为 17，默认启用 `research_efficiency_mode=bounded`。恢复 13–16 版快照时仍执行原策略，不自动增加搜索、shadow 或新的补证路径。

## 审阅顺序

| 批次 | 主要修改 | 核对重点 |
| --- | --- | --- |
| 1：计量与时间 | `runtime_limits.py`、`model_accounting.py`、`usage_projection.py`、`gateway_ledger.py`、配置与冻结字段 | 任务、角色、用途和父工具归属；模型、工具、任务和运行期限；缓存实报与未报告；SQL 预算不重复计费 |
| 2：固定来源与收敛 | `efficiency.py`、`research_agents.py`、`web/pipeline.py`、`completion.py` | 委派前来源检查；固定 URL 批量读取；跨研究员补证次数；按需求检查片段；完整、部分、资料不足三类结果 |
| 3：结果复用与上下文 | `research_quality.py`、`web_tools.py`、`native_context.py`、`research_models.py`、`team_worker.py` | 只复用验证完成的结果；未知结果隔离；完整证据工件与显示分页分开；交接输入目标 8000 token；研究上下文目标 24000 token |
| 4：界面与验收 | 前端效率面板、用途统计、活动耗时、SSE reducer，以及原生测试和实网脚本 | 已下载与已检查分开；执行结束与交接通过分开；刷新与重连不重复；质量失败不计入节省 |

运行内文档、提取、评估缓存分别计数。SQL 只记录缓存回执和运行进展，完整内容保存在运行目录的 `research-cache/`。Gateway 通过既有签名、nonce 和 fence 校验的内部接口读取；Worker 的缓存写入仍受成员租约守卫保护。没有新增缓存服务，也没有跨用户或跨运行复用。

并发相同计算通过按键锁合并。固定资料分配按需求 ID 去重；改写问题或创建新研究员不会清除进展。下载成功不等于检查完毕，只有相关需求的全部片段经过必要检查才标记资料穷尽。内容隔离或处理失败的片段不计入穷尽。

模型只看到预算内的完整证据记录和分页引用；权威记录仍用于质量检查。`ReadResearchEvidence` 只读取本运行的候选工件，并再次执行来源限制。单条记录超过显示预算时可按 `field` 与 `char_offset` 分段回读正文；片段不会被当作完整证据。连固定标识也无法装入预算时返回明确限制，保留完整工件。超过内部请求体上限的大文档保留正常读取能力和进程内缓存，可能不写持久文档缓存。

## 新配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `research_efficiency_mode` | `bounded` | `baseline` 用于保留原策略及对照；新运行默认优化策略 |
| `max_supplement_rounds` | 2 | 每项需求初次研究之后的补证上限 |
| `max_no_progress_rounds` | 2 | 连续没有新证据、检查范围或覆盖改善时停止补证 |
| `research_context_target_tokens` | 24000 | 触发原生上下文压缩的目标，仍受实际模型窗口约束 |
| `handoff_context_target_tokens` | 8000 | 交接输入目标，按完整记录取舍；完整证据不丢弃 |

配置 API、前端设置与中文 `.env.example` 已同步。原文读取继续不是已审核证据；候选只有经过现有交接门禁才进入正式报告。预算或时间不足的确定性部分报告明确显示未执行模型复核，不能显示为复核通过。

## 验收方法

真实模型对照脚本：`tests/as_runtime/run_efficiency_e2e.py`。同一模型与配置，原策略和优化策略交替执行；复杂固定来源、简单固定来源、公开 Web 每类每策略三次。研究期限为 3600 秒，观察期限为研究期限加 300 秒；发布及清理单独处理。资料、模型、参数与内容版本发生差异时须在结果中注明。

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe tests/as_runtime/run_efficiency_e2e.py --policies baseline bounded --cases complex simple web --repeats 3 --output output/research-efficiency/live
```

该脚本只自动处理明确用于验收的计划、大纲及公开测试域名授权，不自动追加预算。非终态观察异常会尝试受控取消。成功需产生有已准入来源的报告并发布成功；启用 Reviewer 的案例还必须复核通过且没有降级。单独保留失败、无证据、复核降级和未完成计费样本，不将其作为效率收益。

费用优先采用供应商或 LiteLLM 可核验账单字段。提示词缓存命中不扣减总输入 token；读取、写入字段未报告时保持未知，不显示为确定零。无法确认供应商内部请求次数时保持未知。内容处理复用次数与供应商提示词缓存分别统计。

本次专用 Compose 项目为 `insightforge-efficiency-e2e`，控制台端口 8088，LiteLLM 接口端口 4108。仅启动本项目的必要服务；验证后停止这些容器及浏览器进程，保留数据库卷和审计工件。

### 复杂固定来源仍未完全通过

三个优化样本均发布了有准入来源的报告，资源观测中位数为 20 次模型调用、138,746 输入 token、154,048 总 token、5.58 分钟及 $0.025325。范围分别为 18–20 次、119,449–141,503 输入 token、5.48–8.25 分钟、$0.022965–$0.031611。工具调用为 2–3 次，抓取结算均为 3 次。

这些数值落在预定资源目标内，但三次最终 Reviewer 均给出 revise/degraded，因此**复杂场景的完整验收未通过**，上述资源观测不作为等质量节省结论。复核没有发现硬门禁或确定性失败；剩余意见包括“较早备份”被概括为“基础备份”的推断、备份保留策略的轻度引申，以及同一句内重复引用。研究简报扩展出的未验证内容均保留为缺口。没有修改质量门槛或将这些意见改写为 pass。

### 缓存、恢复与显示

真实回执中三个复杂优化样本的缓存读取分别为 20,288、26,048、7,040 token，分别覆盖 18、20、20 次已报告调用。它们仍计入总输入 token，缓存写入未报告时显示未知。本轮另外修复了后到账单覆盖原始缓存字段的问题，最终导出已合并两类事实，并保留初始导出供核对。

缓存结果仅在本运行内复用；缺少或未知外部结果不会自动重试。恢复测试覆盖 SQL fence、预算回执、并发复用和崩溃后工具不重复执行。终态总耗时改用持久化起止时间，界面不再将已完成运行显示为“运行中”。

固定来源对照的三个页面内容哈希在 12 次运行中一致。公开 Web 的来源集合允许随发现结果变化；完整内容版本清单见 `output/research-efficiency/verified-live/source-versions.json`。
