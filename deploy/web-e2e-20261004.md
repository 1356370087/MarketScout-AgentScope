# 2026-10-04 Docker 实网验收记录

当前工作区构建部署到独立项目 `insightforge-web-e2e-20261004`。实际链路为 AgentScope → Gateway → LiteLLM/联网工具 → PostgreSQL 回执 → 质量门禁 → 报告与发布；没有使用合成搜索响应。模型沿用本地配置的 GLM 路由。凭据只在本地环境与运行 Vault 中传递。

## 发现并修复

1. 配置验证与启动诊断仍强制沙箱必须使用异步研究，阻止已具备 Gateway/SQL 端口的原生同步研究启动。移除调度模式限制，保留签名、策略、Gateway 端口与 SQL 计量检查。
2. 数据库已迁移至 `0018_knowledge_execution`，启动探针仍要求 `0017_agent_teams`，错误禁用资料能力。同步启动检查版本。
3. Web 发现和最终 URL 检查只执行来源选择，未沿用质量门禁的官方来源/显式禁止约束。由宿主恢复快照通过已认证的预算响应下发覆盖契约，公共 URL 准入复用既有来源分类器。
4. 中文官方来源、引用数量、报告语言、篇幅及范围排除指令被当成事实需求委派；原子拆分还会将分类结果强制改回事实。修正分类并以实网问题补回归。
5. 并发查询首次等待出网审批时，被误报为渠道失败并丢弃查询。在已预留的操作内等待决定，对同一目标串行处理一次性授权；旁路探测仍不创建审批。
6. Gateway 已返回明确工具失败，宿主却将 Web 操作当成执行结果未知而隔离整轮。保留结构化失败及确认标记，提交确定回执；丢失响应的调用继续隔离，已结算调用不重新执行。
7. E2E 的网络审批按钮选择器沿用旧文案。兼容“允许此次访问”，并增加报告复核断言、运行 ID 和截图工件。
8. Gateway 的 HTTP 服务退出后仍等待代理 `serve_forever()`，容器停止需被强制终止。利用 `start_server` 已开始监听的语义，由 HTTP 服务生命周期退出代理上下文，关闭监听器。
