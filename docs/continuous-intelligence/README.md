# MarketScout 持续情报实现

本目录说明持续情报领域的实现、运行条件及验收边界。功能默认关闭，启用不等于质量验收通过。上线步骤见 [运行手册](runbook.md)，测试与未验收项见 [验收记录](acceptance.md)。

## 领域与执行边界

`src/open_deep_research/intelligence/` 位于单次研究引擎之上。API 生命周期中的 `Coordinator` 调度来源与研究事项；独立 `intelligence.worker` 领取采集、影响研判、资料转换和通知任务。研究仍调用 `NativeRuns.create_automated()`，没有第二套 Agent 执行服务。

业务迁移 `0023_continuous_intelligence` 接在 `0022_team_task_fields` 后，添加计划、不可变授权版本、来源、快照、事件、研判、事项、关联 Run、任务、费用预留、通知和绑定表。实体使用现有审计字段约定。文档任务新增可选 `intelligence_binding`，使引用快照的资料摄取仍按原负责人计费。

| 边界 | 实现 |
| --- | --- |
| 观察位置 | `intelligence_sources.sequence`、`snapshot_id` 与发布日志游标；304 和正文未变化均推进检查时间 |
| 研判位置 | 事件状态及 `intelligence_decisions`；重放已经提交的研判，不重新调用模型 |
| 已发布基线 | `intelligence_plans.baseline`；只在人工关联已发布结论或确认发布成果时更新，并增加计划版本 |
| 自动授权 | 计划负责人、授权版本、当前 IAM 状态、`authz_version` 和知识库权限；不建立登录会话或保存浏览器 Token |
| 输入冻结 | 服务端生成快照清单及哈希，进入 v24 Run 指纹；运行期间的新快照不替换旧输入 |
| 正式证据 | 观察原文经 `ReadObservation` 和原生证据提取准入；直接阅读原文不等于证据通过 |
| 正式知识 | 原始快照转普通资料草稿 → 人工发布资料 → 原文对应校验 → Wiki 草稿 → 人工发布 → 更新基线 |

新计划默认 `observe`，允许采集及预算内的研判。`auto` 需要预览确认来源、动作、到期时间及费用。观察模式可以显式发起研究；暂停停止新的后台采集和自动派工，已运行研究可完成草稿。撤权、账号停用、权限丢失、到期会在下一安全检查点阻止操作并取消关联活动 Run。已经发出的请求不能瞬时撤回。

计划绑定一个工作空间和知识库。团队可以查看事项中的成果、准入证据及状态；普通 Run 的完整私有会话仍保留原所有权边界。负责人转移会暂停计划并撤销旧授权，新负责人需要自行授权，历史 Run 费用不变。

持续研究的跨 Run 上下文来自计划历史和已授权知识基线，关闭负责人个人研究记忆的召回与写入，避免将其他私人研究带入团队成果。普通一次性研究保留原有记忆能力。

## 质量和兼容性

新研究默认启用研究质量评估与报告审阅，默认关闭两类 fail-open。一次性研究可以显式关闭语义评估，但确定性准入仍执行，界面保留未评估状态；持续研究拒绝宽松配置。

v23 起恢复交接及确定性完成策略；Adaptive、同步委派、collaborator 和 Teams 复用 `assess_handoff()`。原始材料保留，只有准入的结论和证据进入正式报告。摘要错误且原证据充分时最多修复一次，不因摘要错误重新搜索。需求补证计数和无进展状态沿用恢复账本；报告修订使用既有预算预留与有界循环。

Judge 协议错误、不可用、缺少输入和预算不足不会转换为通过。未完成的研究可以形成明确标记的部分成果，未通过的报告审阅稿被保存。持续情报对执行状态和质量状态分别判定；只有研究完整完成、交接已评估通过且报告审阅通过的成果可进入转换流程。

新建 Run 当前契约为 v24。v22 按原冻结语义恢复，v23 保留质量执行语义，v24 增加观察清单；旧指纹与已提交回执不重写。保存的用户配置不被批量覆盖。

证据保存抓取时间、可获得的来源日期与可选有效期；未知时间保持未知。新语义不再使用固定 `freshness=0.5`，旧版本保持历史排序行为，不增加未经验证的时间衰减公式。

## 来源和知识事件

网页采集复用公开网络安全检查、条件请求及 HTML/PDF 提取。快照保存原始字节、规范化正文、两种哈希、解析器版本和质量标记，存储在文档共享卷的 `observations/` 下。动态页面壳、空正文、越界重定向与解析失败都会形成明确异常，不记为无变化。首轮采集器支持本地静态 HTML、文本及 PDF 提取；需要浏览器渲染或登录的来源不作为已验收来源。

指定已发布资料使用事务内发布日志与独立游标，避免两次检查间 A→B→A 被内容哈希去重。目标知识库内事实和 Wiki 发布也在发布事务中写事件；内部发布事件来源只提供变化背景，不增加网页或文档取证权限。来自本计划成果的发布事件标为 `self_published`，其他计划继续正常评估。

影响判断只接收变化片段、计划目标、已发布事实和基线背景。服务端校验模型给出的事实和快照 ID；截断变化不能被静默忽略。相关新事件在同计划已有自动研究时等待，不改变在途输入。

## 调度和费用

任务采用条件更新领取、租约与执行代次；写入结果时重新验证代次及租约。业务修改与创建持久任务处于同一事务，网络调用在提交后执行。Run 创建意图先持久化，使用稳定的运行 ID 与幂等键，丢失创建响应后通过原 SQL 回执恢复关联。

同计划研判串行；批次在 5 秒无新事件时收拢，最长合并窗口为 60 秒。默认 4 个自动研究槽位、每计划 1 个；人工反馈和取消走控制队列，不等待研究槽位。停机恢复检查最新到期状态，不补跑每个错过的时刻。

个人月度配额负责真实模型账单，计划额度是附加约束。研究、语义研判及由观察转换产生的资料摄取都预留计划额度。已知回执按实际费用结算；未知模型结果保留占额并转人工处理。费用核对只依据可信原生/服务调用回执，不能因回执缺失或点击取消而释放预留。外部搜索等非模型费用不纳入美元账本，仍受工具次数和服务配额约束。

网络失败有限重试；429 遵循秒数或 HTTP 日期形式的 `Retry-After`。持续来源失败停止后续定时采集并留待办，人工检查或重新授权可以重置。需要扩大来源时暂停并等待重新授权。

## 界面及接口

界面为 `/intelligence`、`/intelligence/plans/[planId]`、`/intelligence/items/[itemId]`。列表每 5 秒刷新，身份和工作空间进入查询键；具体 Run 继续使用原 SSE。BFF 延用 HttpOnly Cookie。

`/intelligence/plans` 管理计划，`activate`、`pause`、`archive`、`authorizations`、`transfer` 管理生命周期；`check` 发起来源检查；`baseline` 关联已发布结论；`requests` 发起人工复核；`events`、`decisions` 提供依据；`items/{id}/actions` 支持启动、反馈、取消、恢复、忽略及补充研究；`review` 进入人工发布流程；`snapshots` 提供有界原文；`inbox`、`health`、`reconcile-budget` 提供待办和运营状态。

编辑、审阅和有副作用的事项动作带对象版本及命令 ID。并发冲突返回当前版本；同命令内容不一致被拒绝。观察清单和后台身份不允许由普通 HTTP 请求注入。
