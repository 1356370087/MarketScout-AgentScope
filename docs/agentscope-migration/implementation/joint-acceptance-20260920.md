全部九次研究尝试的 LiteLLM Run Key 累计费用合计 **0.237391 美元**，包含失败和取消调用；末次读取数值稳定。详见 [逐运行账单](../evidence/joint-research-costs-20260920.json)。取消运行仍有 started 操作和 SQL 预留，Web 失败也有一个 started 操作，未将这些改成零或删除；Run Key 实际费用与 SQL 已提交用量分开保存，不能把 SQL used 单独冒充完整财务审计。

关键发现：

1. **真实资料工具修复有效，但研究尚未闭环。** 资料独立复验的 Gateway 账本记录 45 次成功的 `search_documents`，每次返回 4 条资料证据，未再次出现 UnknownOperation。随后仍缺少接纳证据、独立来源和部分覆盖，最终迭代耗尽；反复查询同一资料没有解除完成门禁。
2. **指定来源约束与来源数量门禁冲突。** 该样本只允许一个官方 URL，交接账本明确记录 source_count=1 / required_source_count=3，并建议追加其他官方页面；追加页面又不在本次 exact URL 来源范围。不能通过越界抓取或临时降低最少来源数关闭问题。
3. **真实报告预算缺口仍存在。** Web 运行依次生成初稿、引用修复、两次评审、修订和证据受限草稿；在恢复草稿再次评审时，经 `_ReportRun.invoke` 的候选模型预算适配抛出 ReportInputBudgetExceeded。完整报告没有提交为成功，记录的错误类型及调用栈足以定位阶段，但本轮未完成固定输入的最小根因复现，不把该问题简单归因为“报告太长”。
4. **混合来源运行进入人工出网边界。** 请求限定官方资料，但出现第三方 `bucardo.org` 链接。未绕过审批。该次没有完成混合研究质量验收。

原始请求、SQL 状态/预算/工具回执、报告回执和异常帧保存在忽略目录 `tmp/joint-acceptance-20260920/`；没有手动修改任何真实运行账本。
