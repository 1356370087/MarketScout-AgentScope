# 原生入口清退前置能力补齐（2026-09-21）

完整目标仍是删除 QueryEngine 及旧配套执行代码，将剩余能力接入 AgentScope，并完成端到端验收。本记录仅证明本批代码和验证范围，整体进度保持 67/81。

## 发现与变更

- 清退盘点仍有 72 处 LangChain 导入、13 处旧引擎导入。`server.py` 默认创建 QueryEngine，原生模式通过前置路由覆盖研究路径；删除/保留策略等外围路径仍需迁移。详见 [当前盘点](../evidence/retirement-baseline-20260921.json)。本轮没有修改盘点规则来隐藏导入。
- `tests/run_evaluate.py` 原来直接构造 QueryEngine，Judge 也走旧模型栈。现复用 `run_native_question` 和 `native_judge_session`，传入完整消息、参考答案，保留失败/未评分状态。LangSmith SDK 延迟至显式远程入口导入，依赖声明为 `evaluation-langsmith`；`uv lock --offline` 已更新锁文件。本轮没有向 LangSmith 发起远程实验。
- 原生创建路由绕过旧宿主的创建频率、并发运行和 SSE 限额。现抽取 `api/admission.py` 共用原策略，宿主和 NativeRuns 共享限流器。创建限额读取部署配置，SQL 非终态运行参与计数，等待审批也占用并发名额；幂等重放不会创建新名额。单 Worker 内锁覆盖检查和持久化插入，防止并行请求同时通过计数检查；不承诺多 Worker 全局限流。
- 原生研究/发布 SSE 统一占用连接额度，StreamingResponse 在断连、取消和发送错误后释放一次。流式创建先取得连接名额；创建失败同样释放。测试也覆盖提前断连不误释放其他请求的名额。
- 原生启动以前没有扫描 SQL 中的中断运行，仍调用旧文件恢复 sweep。现自动发现 ready/running 及已有待消费决定的 waiting 运行；有效租约不会被接管，未回答的审批和失败/取消/完成状态不会自动重启。恢复继续使用原有操作回执，未知提供商执行结果仍进入隔离，不能重新调用。
