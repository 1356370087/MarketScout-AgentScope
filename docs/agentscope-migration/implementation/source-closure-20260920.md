## 定位与实现

| 问题 | 复现证据 | 修复 |
|---|---|---|
| 指定一个 URL，却要求三个来源 | 原 Specific 的来源选择在 API metadata 中，但没有进入覆盖契约；工具评估、ResearchComplete、交接和主管完成判断使用不同来源口径 | 把冻结的结构化来源选择写入契约并传给 Judge；有限来源集合派生任务与汇总的来源要求，各阶段复用同一规则。全局 `quality_evaluation_min_sources=3` 不变，普通 Web/Hybrid/域名范围仍保留原数量要求 |
| 单 URL 中文引用被错误判为越界 | 真实压缩结果中的 `release-17.html（` 被当成 URL，虽然实际引用仍是指定页面 | URL 提取排除中文标点；真正的其他页面仍拒绝 |
| 资料检索成功却无法登记证据 | 原资料复验 45 次 `search_documents` 成功，返回的 `locator` 是字典；`EvidenceRecord.locator` 只接受字符串，观察器反复校验失败，任务不能形成交接 | 证据模型保留结构化定位信息；同样修复报告评估快照的 `EvaluationEvidence.locator` 类型，使资料从检索贯通到报告 |
| 审批等待被误判为任务失败 | 专用真实用例的 `_worker_error=ApprovalPending`，随后主管迭代耗尽、运行失败，审批控件失效 | 原生 Gateway dispatcher 在同一工具调用、同一操作标识内重新附着 Gateway 的已有长轮询；只处理明确的待审批响应，不重试其他错误。取消仍可中断等待，批准或拒绝均交由 Gateway 重新裁决 |
| 报告复核引用格式与来源范围不明确 | 模型把文件名/章节填入 `citation_target`，或把摘录内尚未准入的链接复制成引用 | 补齐引用目标字段说明；统一写作规则明确只引用记录的 `source_url/source_uri`，摘录内的链接仅是材料内容。保留原引用校验和 fail-closed 行为 |

来源数量不是把一个文档的多个片段伪装成独立来源：资料按文档去重，网页按既有页面身份去重，主管完成判断与交接门禁采用相同口径。有限集合中，叶任务可负责其中一个来源，汇总要求为配置值与已授权来源数的较小者；需求覆盖、证据准入和引用检查仍照常执行。空证据的单 URL 抓取也不能完成。

知识库/集合选择沿用运行创建时冻结的文档展开结果。指定 URL 和未选文档的拒绝检查与网络授权相互独立：已有域名访问许可仍不能抓取未选择的路径、不同查询参数页面或其他站点。
