# E2E P0/P1 编码收口记录

日期：2026-09-18。以用户要求的最新工作区为基线，包含此前尚未提交的 T023 物理模型计账、生产资源及正式 Worker 实现。此次仅一次本地 Git 提交，不推送。

## 已交付的实现

- Controller 团队启动：新增签名/防重放 UDS 端点，部署层固定镜像、命令、环境文件、网络与挂载。API 不安装 Docker CLI、不持有 Docker socket。团队容器按 run/fence 命名，复用活跃容器、有限重启、逐任务清理；正式 Worker 监测领队 SQL 租约，失租时退出。
- 原生审批：共用服务器的所有权桥、审批/egress 上下文改为识别原生 SQL 运行。事件经可注入发布器写入 SQL outbox，沿用已有公共事件过滤，统一游标与去重；旧引擎分支保留。
- 资料来源：创建阶段授权所选资料并将发布代次快照写入原生应用检查点；执行与恢复复用快照建立不可变 run_sources。私有检索在可信控制 Worker 的受治理 HOST_CONTROL 区执行，不开放 shell/file 本地执行。Gateway Web 工具保留来源选择约束。
- 生命周期：任务令牌按请求刷新；Run Key 与 Gateway 注册周期续期，外部续期不阻塞 SQL 心跳锁。冻结代理默认成本上限，恢复按 SQL 已用/预留后的剩余预算申请新 Key；修正孤儿 Key 替换忽略请求预算的路径。旧 Key 清理器先识别 SQL 租约，保护活跃原生运行、回收失租执行段。
- 计账：保留每个应用可见物理尝试的回执，增加 LiteLLM run/operation 标签、可信账单读取、迟到记录后台补回、幂等差额结算和管理员补核对命令。补账不改变模型回放内容，不重复增加调用次数。缺失或多笔代理账单保留未决，未知执行结果不自动重放。原生 `/runs/{id}/usage` 读取 SQL 账本，区分报告值和估算值。
- E2E：新增四来源真实 BFF/浏览器用例，覆盖审批、完整报告、引用、刷新、用量、发布与下载；失败后取消本次运行。增加受专用项目限制的 Worker 强杀、API/Gateway 同时强杀模式，等待原租约自然到期后恢复。未命中故障窗口不能通过。
- 部署：新增原生 Compose 覆盖、Worker 中文示例环境文件和执行脚本。脚本只使用本次专用项目，finally 停止其服务并清理新增团队容器，保留数据卷和验收工件。

部署和命令见 [原生 E2E 操作说明](../../../deploy/native-e2e.md)。

## 仍未关闭的验收边界

本轮没有执行真实付费模型与搜索的四来源浏览器 E2E，也没有执行新加的正式 Controller Worker / API+Gateway 同故障 live 批次。跨主机网络分区、长时真实代理续期、上游供应商逐次账单核验仍待实际环境证据。脚本实现与确定性组件成功不替代这些验证。

可信代理单条账单可以自动关联补回；代理重试产生多笔账单、无法证明最终账单完整或模型结果未知时仍保留隔离，需要提供商/代理明确回执核验。不能据此宣称上游每次付费尝试均已对平。

M8 的完整知识共享权限/真实 Mem0、备份恢复，M11 的完整 tracing/质量对照、历史切换与旧循环退出继续按原任务跟踪。没有将它们顺带改成完成。正式计数保持 37/81；T075 从待开始改为进行中，其余受影响任务更新最新实现与验收证据。
